# Especificaciones de cambios

Los cambios T1 y T2 deben documentarse antes de implementar en specs/NNN-feature-name/.

- spec.md: problema, objetivo, alcance, requisitos y criterios de aceptación.
- plan.md: diseño, archivos afectados, orden, pruebas y riesgos.
- tasks.md: tareas pequeñas y verificables.

Usa las plantillas comunes de project-quality: https://github.com/AlexFrigenti/project-quality/tree/main/specs/000-template

Para Núcleo, los criterios deben relacionarse con regresiones, build, artefactos generados, versión, PWA o revisión visual cuando correspondan. No se inventan controles que el proyecto no necesita.
